# Design decisions

These records explain why Netjes is built the way it is, for contributors and for anyone weighing it against another framework. Each one states a decision, the context that led to it, the alternatives considered and what follows from it. [The architecture page](../architecture.md) describes how the pieces fit together; these records say why they are those pieces.

- [0001 – React renders in a pool of Node sidecars](0001-react-renders-in-node-sidecars.md): supervised Node processes render React, and .NET balances renders between them.
- [0002 – The server owns routing](0002-server-owns-routing.md): routes are matched in C# only, and the client router asks the server for every page.
- [0003 – React renders the whole document](0003-react-renders-the-whole-document.md): React renders `<html>` itself, head and metadata included.
- [0004 – Vite for the dev server and builds](0004-vite-for-dev-server-and-builds.md): Vite serves modules in development and builds the client and server bundles.
- [0005 – A small default stack](0005-a-small-default-stack.md): React, TanStack Query, Tailwind CSS and Vitest, with no other runtime dependencies.
- [0006 – Types and zod schemas generated from the C# contracts](0006-types-and-zod-from-csharp-contracts.md): the running app writes `generated/netjes.ts` from its System.Text.Json contracts.
- [0007 – A Node CLI in the npm package, which asks the app itself](0007-a-node-cli-that-asks-the-app.md): `netjes` runs the app in command mode to report its routes and types.
- [0008 – Image processing is pluggable, SkiaSharp optional](0008-pluggable-image-processing.md): the image endpoint owns the rules, and a separate package resizes.
- [0009 – Public configuration is sent at runtime](0009-public-config-at-runtime.md): `Netjes:PublicConfig` reaches the browser with the first document, not through the build.
- [0010 – The App Router's conventions, with C# layout loaders instead of server components](0010-app-router-with-csharp-layout-loaders.md): `app/` only, and each segment's data comes from C#.
- [0011 – Server actions are C# endpoints with typed references](0011-server-actions-as-csharp-endpoints.md): stable names, antiforgery and origin checks, and forms that work without JavaScript.
- [0012 – Streamed documents, deferred values, and ready boundaries in place](0012-streamed-documents-and-deferred-values.md): documents stream, `Page.Defer` values follow the shell, and ready boundaries need no script.
- [0013 – A client-rendered fallback when no sidecar is ready](0013-client-rendered-fallback.md): .NET sends the payload for the browser to render while Node is down.
- [0014 – Signing in or out clears what Back shows](0014-signing-in-or-out-clears-what-back-shows.md): a cookie change in an action makes the router and the browser forget pages.
- [0015 – Route warnings name what is likely wrong, not everything that could be](0015-route-warnings-name-what-is-likely-wrong.md): startup warnings for query-bound loader parameters and overlapping pages.
- [0016 – Page cache rules under any output caching](0016-page-cache-rules-under-any-output-caching.md): page keys, tags and token rules apply whatever policy caches a page.
- [0017 – A form input without any of its fields is empty, not null](0017-a-form-input-without-fields-is-empty-not-null.md): an action gets an empty `[FromForm]` input, checked like any other, where form binding gives none.
- [0018 – A startup failure that says what to do ends the app in one line](0018-startup-failures-end-in-one-line.md): a missing build, Node.js or Vite dev server is one log entry and exit code 1, and a failed start in a test host.
- [0019 – A forced no-store removes the headers CDNs read first](0019-forced-no-store-removes-cdn-cache-headers.md): drafts, the fallback and the other `no-store` responses go out without `CDN-Cache-Control`, `Surrogate-Control` and the like.
- [0020 – Page actions check their inputs like server actions](0020-page-actions-check-their-inputs-like-server-actions.md): a failed check renders the page again from its loader, and `usePageActionState()` reads it.
- [0021 – Signing in or out reaches the app's other tabs](0021-signing-in-or-out-reaches-the-other-tabs.md): a tab that sees a cookie change tells the others on a `BroadcastChannel`, and they forget and reload the same way.
- [0022 – The client entry hydrates once the shell is parsed](0022-hydrate-once-the-shell-is-parsed.md): it waits for the empty element that ends every document's body, so a cached entry never hydrates half a document.
- [0023 – Pages are not output-cached in Development](0023-pages-are-not-output-cached-in-development.md): there every request renders the page, nothing is stored, and the page goes out `no-store`, so no edit meets a stale document.
- [0024 – Link marks the current page by its path and the query parameters it names](0024-link-marks-the-current-page-by-path-and-query.md): `aria-current="page"` goes on a link to the page on screen, never on a `#` link, and query parameters the link does not name do not count.
- [0025 – A mark on `<html>` says the client router runs](0025-a-mark-on-html-says-the-client-router-runs.md): `data-netjes-hydrated` appears once the router is the page's action client, in every document, and end-to-end tests wait for it rather than for `history.state`.
- [0026 – Netjes's own `<html>` and `<body>` skip React's attribute check](0026-netjes-html-and-body-skip-reacts-attribute-check.md): a script that sets an attribute on either one before hydration, such as a theme script or a browser extension, no longer makes React log a mismatch in development.
- [0027 – Testing Library advances Vitest's fake timers through a jest global that exists only while they are on](0027-testing-library-advances-vitest-fake-timers.md): a setup file the plugin adds to every app's tests bridges `jest.advanceTimersByTime` to Vitest while its timers are fake, so `waitFor`, `findBy` and user-event return.
- [0028 – The test harness starts from the app's query defaults and keeps its retries, without the waits](0028-test-harness-starts-from-the-apps-query-defaults.md): `createTestApp` layers the app's `netjes({ query })` defaults, which the plugin provides to the tests, under its own `retryDelay: 0`.
- [0029 – An endpoint that ties with a page is a route warning](0029-an-endpoint-that-ties-with-a-page-is-a-route-warning.md): an endpoint of the app that ranks the same as a page or a page action, which ASP.NET Core answers with 500 for the URLs both match, is warned about at startup and in `netjes routes`.
- [0030 – Security headers beyond documents](0030-security-headers-beyond-documents.md): `nosniff` goes on every response through `UseNetjes`, and documents carry the `X-Frame-Options` their `frame-ancestors` implies, set before antiforgery could add its own.
- [0031 – A sidecar that stops answering is restarted like one that crashed](0031-a-sidecar-that-stops-answering-is-restarted.md): in production a Node process silent for five seconds is pinged, and killed and restarted when no answer comes within `RenderTimeout`.
- [0032 – The release links the package READMEs to its tag](0032-release-links-package-readmes-to-its-tag.md): the READMEs link the docs on `main`, and the release job moves those links to `v<version>` in the packages it publishes, so npm and NuGet show each version with links to its own docs.
- [0033 – Client navigations announce the page and start the focus over](0033-client-navigations-announce-the-page-and-start-the-focus-over.md): a polite live region names the new page, and the focus starts over at the top of the document or goes to a fragment's element; it stays on the same page, where the page or the user moved it, and in a field or on a `scroll={false}` link that still has it.
- [0034 – Navigation promises resolve when React has the page](0034-navigation-promises-resolve-when-react-has-the-page.md): `router.push`, `replace` and `refresh` resolve once the router has handed the page to React, not once React has committed it, which inside a form action would never happen.
- [0035 – Development styles are inlined from the client environment's build](0035-development-styles-are-inlined-from-the-client-build.md): the sidecar inlines the CSS text that the browser's module for each file sets, so Vite's client changes nothing before hydration, and React no longer checks the text of those elements.
- [0036 – zod runs without compiled parsers in the browser](0036-zod-runs-without-compiled-parsers-in-the-browser.md): the client entry's first import sets zod's `jitless`, so no policy without `'unsafe-eval'` reports zod's test for `new Function`, and the sidecar and Vitest keep the compiled parsers.
- [0037 – Netjes keeps an app's Content-Security-Policy as written in Development, and warns](0037-csp-kept-as-written-in-development-with-warnings.md): the policy goes out as written in every mode, and Netjes warns once per policy when it refuses the bootstrap or the module scripts, holds a nonce that is not the document's, or in Development refuses the Vite dev server's scripts, its socket or the inlined styles.
- [0038 – `netjes/testing` renders a page's document from its props](0038-netjes-testing-renders-a-pages-document.md): `renderDocument` builds the payload from the pages map by the server's rules, which a fixture shared with the C# tests keeps the same, instead of `netjes/server-entry` and its payload becoming public.
- [0039 – A page URL has one spelling](0039-a-page-url-has-one-spelling.md): a `GET` or `HEAD` for a page in another case of its literal segments, and with `TrailingSlash.Never` one with a trailing slash, answers 308 with the file's spelling, built from the URL the client sent.
- [0040 – Links from C# are a Href type](0040-links-from-csharp-are-a-href-type.md): a `Netjes.Href` in props is checked for its shape in C# and generated as the `Href` schema, which checks it against the app's pages where the props are parsed, so a component passes it to `<Link>` as it is.
- [0041 – The export warns about loaders that read the query string](0041-the-export-warns-about-loaders-that-read-the-query-string.md): a static host serves an exported page's file for every query string, so `netjes export` logs a warning for each such loader, in `Netjes.Export.QueryString`, and still writes the page.
- [0042 – The app's image runs an init as PID 1, so a crash ends the container](0042-the-apps-image-runs-an-init-as-pid-1.md): the template's and the examples' production images start the app with `tini -s --`, so a crash ends the container with code 134 and `docker stop` reaches the app, where .NET as PID 1 spun or exited with another code.
- [0043 – Netjes marks the errors whose message it withheld](0043-netjes-marks-the-errors-whose-message-it-withheld.md): `error.withheld` is true on an error whose message Netjes wrote in place of one it does not show, so an error page renders the message only when `!error.withheld`, and the router's top-level boundary hands the app's error page the error it caught.
- [0044 – `beforeInteractive` scripts run before the page's code](0044-before-interactive-scripts-run-before-the-pages-code.md): inline code runs where it stands, before what follows it is painted, and external scripts run in order once the shell is parsed, before the page's modules run and the page hydrates.
- [0045 – Typed URLs for the app's endpoints](0045-typed-urls-for-the-apps-endpoints.md): the generated `endpointUrl()` builds the URL of each endpoint of the app that is not a page, JSON or not, by its key in `api`, with the route values and query values its handler binds typed in TypeScript as binding accepts them, and without the base path, which `useHref` adds.
- [0046 – The export writes the GET endpoints marked IncludeInExport](0046-the-export-writes-the-get-endpoints-marked-includeinexport.md): `netjes export` writes the answer of each endpoint marked `.IncludeInExport()` as a file at its URL, `MapSitemap` and `MapRobotsTxt` among them, and the exported sitemap lists the pages the export writes.

A decision that a newcomer would not guess, or that was chosen over a real alternative, gets a new record with the next number. An accepted record is not rewritten when the decision changes; a new record supersedes it.
