# 0003 – React renders the whole document

Status: accepted

## Context

Pages need to set their `<title>` and meta tags, and the document needs the asset tags of the build. Either .NET builds the HTML shell and React renders into a `<div id="root">`, or React renders `<html>` itself.

## Decision

React renders and hydrates the entire document (`Document` in `packages/netjes/src/document.tsx`). .NET puts the asset list, the language and the document's other settings into the payload. Titles and meta tags use React 19's support for `<title>`, `<meta>` and `<link>`, which hoists them into `<head>` on the server and keeps them in sync on the client. The Metadata API (`export const metadata` in pages and layouts, `.WithMetadata(...)` from a C# loader) renders its tags the same way.

## Alternatives considered

- **A shell generated by .NET with a root div.** It gives .NET full control of the head, but React 19 then cannot place `<title>` in the head during SSR, so Netjes would need a `<Head>` component with its own collection and client-side syncing.

## Consequences

- No head manager to learn: a page renders `<title>`, or exports `metadata`.
- React 19's hydration tolerates browser extensions that inject elements into `<head>` and `<body>`.
- React renders the payload into a `<script type="application/json">` element, and the client reads it back as it is for hydration. The server escapes it for HTML.
- .NET writes the document's head itself while no sidecar is ready ([ADR 0013](0013-client-rendered-fallback.md)), so it keeps a copy of what `Document` renders there.
